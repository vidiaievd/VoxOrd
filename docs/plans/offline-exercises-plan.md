# VoxOrd: готовность к тестированию и офлайн-режим упражнений

> Заведён 11.10.2026. Состояние на эту дату: телефон играет все 20 шаблонов (PR #15–#19, ждут мержа
> в `dev`), но **ни одно упражнение не работает без сети** — каждое открытие и каждая проверка идут
> в exercise-engine. Решения владельца: офлайн нужен для слов и для материалов курса; материалы
> скачиваются **автоматически**.

Документ из двух частей:

- **Часть A** — что осталось, чтобы владелец мог отдать приложение в детальное тестирование. Это
  короткий список; после него работа переходит на адаптацию курсов к новым упражнениям.
- **Часть B** — план офлайна: общая инфраструктура, затем каждое упражнение до автономной работы.
  Часть B не блокирует тестирование и выполняется после адаптации курсов или параллельно с ней.

## Модели

| Метка | Модель | Когда |
|---|---|---|
| **O** | Opus 5.5 (`claude-opus-5-5`) | контракты между сервисами, миграции локальной БД, синхронизация, всё, где ключ ответа может утечь, судьи с дозированием подсказок |
| **S** | Sonnet 5.5 (`claude-sonnet-5-5`) | тело или порт по готовому образцу, эндпоинт по готовому контракту, тесты |
| **H** | Haiku 5.5 (`claude-haiku-5-5`) | строки i18n, документы, механические правки по готовому списку |

Правила проекта для каждого шага: маленький шаг → проверка владельцем → следующий; пакеты владелец
ставит сам (шаг их только перечисляет); `npm run lint` в сервисах не запускать целиком (`--fix`
переписывает чужие файлы); prettier в VoxOrd — только по своим файлам.

## Часть A. Что осталось до детального тестирования

### A1. Влить ветки — владелец
PR #15 → #16 → #17 → #18 → #19 в `dev` по порядку (у агента нет права мержить без ревью). #19 собран
поверх локального мержа остальных — после них его дифф сожмётся до четырёх коммитов.

### A2. Тестовая сборка, которая работает без провода — **S**
Сейчас приложение живёт на Metro и `adb reverse`. Для теста на руках нужно:

1. **HTTP в release-сборке.** `AndroidManifest.xml` берёт `usesCleartextTraffic` из плейсхолдера:
   в debug — `true`, в release — `false`, и release-APK не достучится до `http://` стенда. Для
   внутреннего теста выставить плейсхолдер `true` для release в `android/app/build.gradle` (или
   `network_security_config` с адресом стенда). Перед публикацией вернуть.
2. **Адрес сервера.** По умолчанию `http://10.0.2.2:80` (эмулятор). Меняется в «Настройки →
   Разработчик». В инструкцию для тестировщика: IP компьютера в домашней сети (`192.168.50.x`).
3. **Аудио и картинки по Wi-Fi.** media-service отдаёт подписанные ссылки на MinIO с хостом
   `localhost:9000` — по проводу это закрывает `adb reverse tcp:9000`, по Wi-Fi — нет. Задать
   `MINIO_PUBLIC_BASE_URL=http://<IP-компьютера>:9000` в `.env.dev` и пересобрать media-service
   (`--env-file .env.dev`, `up -d --build`). Проверить, что подпись не ломается сменой хоста —
   см. памятку про цепочку багов загрузки (подмена хоста после подписи).
4. **Сборка APK.** `cd android && ./gradlew assembleRelease` → `app/build/outputs/apk/release/`.
   Подпись — debug-ключ, для внутреннего теста достаточно. Проверить на телефоне: вход, курс,
   юнит, по одному упражнению каждого типа, аудио, запись голоса.

### A3. Отлов падений — **S**
В приложении нет ни `ErrorBoundary`, ни отчётов о падениях: тестировщик увидит красный экран
(debug) или молча закрывшееся приложение (release) и не сможет описать, что случилось.
- `ErrorBoundary` вокруг `RootNavigator`: экран «Что-то пошло не так» + кнопка «Скопировать отчёт»
  (сообщение, стек, экран, версия) — без внешних сервисов.
- Версия и номер сборки в «Настройки → О приложении», чтобы отчёт ссылался на сборку.

### A4. Известные дефекты, которые тестировщик найдёт первым — **S**
| Что | Где видно | Откуда |
|---|---|---|
| Упражнение помечено «Пройдено» после непройденной попытки | список юнита (`information_transfer`, серверные типы) | завершённость пишется по факту попытки, не по `passed` — **решение владельца**: по первой проверке или по порогу |
| Сетка «Ежедневная тренировка» на главной открывает выбор режима, а не режим | главная | `RootNavigator` игнорирует `modeId`; уйдёт вместе с колодами (B-фаза слов) — сейчас либо починить в одну строку, либо скрыть сетку |
| Демо-колоды «Повседневное / Технологии / Еда» на главной | главная | `src/db/seed.ts`; тестировщика собьют с толку — скрыть до B1 |
| Карточка ридера: «Complete the exercise.» вместо инструкции автора | ридер, все типы | общая инструкция страницы перебивает `card.defaultInstruction` (аудит 34 §14.7) |
| Нет языка интерфейса `nb` | настройки | только `en/uk/ru`; для теста не блокер |

### A5. Чек-лист для тестировщика — **H**
`VoxOrd/docs/testing/checklist.md`: вход/выход, смена языка, курс → юнит → ридер → упражнения,
по строке на каждый из 20 типов (что сделать, что должно получиться, как выглядит провал),
повторение слов, аудио, запись, клавиатура (Gboard, автокоррекция), поворот экрана, убийство
приложения посреди упражнения, потеря сети посреди проверки. Пути валидаторов — `ssz-platform/services/exercise-engine-service/src/infrastructure/validation/validators/`. Источник строк по типам — таблица
части B и записи живых проверок планов 66–73.

**После A1–A5 приложение отдаётся в тестирование, работа переходит на адаптацию курсов.**

## Часть B. Офлайн

### B0. Как это устроено (решения)

1. **Сервер остаётся судьёй.** Телефон проверяет локально, чтобы ученик сразу видел результат, и
   кладёт попытку в очередь. При появлении сети очередь проигрывается, движок перепроверяет всё
   заново и пишет события с исходным временем. Расхождение телефона и сервера решает сервер; телефон
   получает итог и обновляет отметку.
2. **Ключ на устройстве — только для тренировки (`PRACTICE`).** Контрольные (`GRADED`), задания
   учителя с оценкой и пробы плана 63 — только онлайн для любого типа. Для групп 2–3 ключ на
   устройстве — осознанная цена: дозирование подсказок офлайн держится на честности, сервер при
   синхронизации проверяет бюджеты и не засчитывает лишнее.
3. **Логика проверки — из ядра, а не копией.** VoxOrd сейчас переписывает разбор документов руками
   по каждому типу, и копии расходятся с ядром (так сломался перевод с плана 42). `@ssz/shared-kernel` —
   чистый TypeScript без зависимостей; подключаем его к VoxOrd пакетом (B2).
4. **Скачивание автоматическое**: текущий курс — все опубликованные модули с текстами, грамматикой,
   словарями, упражнениями; медиа (аудио, картинки, клипы упражнений) — для открытого юнита и
   следующих двух, **только по Wi-Fi**; обновление — по смене версии модуля. Лимит места и ручная
   очистка — в настройках.

### B0.5. Офлайн-сессия — вход без сервера (заведено 15.10)
Без сети приложение не открывалось: `restore()` при сетевой ошибке refresh ставил `signedOut`
(с флагом `offline`), а навигатор пускает только `signedIn`. Ни B1, ни B3 этого не чинят — всё
скачанное лежало бы за экраном входа. Принцип: войти по паролю без сервера нельзя, продолжить
сессию, уже лежащую на устройстве, — можно (отпечаток при биометрии работает без сети).

| Шаг | Что | Статус |
|---|---|---|
| B0.5.1 | Пользователь последней сессии хранится рядом с refresh-токеном (`src/api/sessionUser.ts`, AsyncStorage), стирается вместе с ним. При сохранённой сессии приложение открывается **сразу** (`signedIn` + `offline`), refresh подтверждает в фоне. Не достучались (сеть, 5xx, 429) — остаёмся внутри; токен отклонён — выход. 401 при недоступном refresh тоже не выкидывает (`handleUnauthorized`). Первый запрос, дошедший до сервера, обменивает токен и снимает флаг | сделано |
| B0.5.2 | Возврат сети: `@react-native-community/netinfo` + `AppState` → `authService.reconnect()` (refresh) → как только сессия онлайн (после reconnect, подтверждённого старта или входа) — по порядку `reviewQueueStore`, `wordCaptureQueueStore`; координатор `src/services/sessionSync.ts`, очереди — списком, `outbox` B3.3/B4 добавится туда же. Обновление кэшей экранов — не здесь: экраны перечитывают сами при открытии | сделано |
| B0.5.3 | Очереди помечены `userId` (`isOwnedBy` в `src/lib/reviewQueue.ts`): при протухшей сессии не стираются, уходят после входа тем же пользователем, чужим — не уходят и не считаются; записи старых сборок без `userId` уходят с тем, кто вошёл. «Выйти» с неотправленным — предупреждение с числом, без сети — ещё и «войти снова получится только с сетью» | сделано |
| B0.5.4 | Плашка над панелью вкладок по `auth.offline` + «ждут отправки: N» (`OfflineSessionBanner`), появляется через 2 с — чтобы не мигать на каждом старте, пока сервер подтверждает сессию. Экраны без вкладок держат свои плашки | сделано |

Ограничение: refresh-токен живёт 7 дней (`RefreshTokenLifetimeDays`). Дольше без сети — после
возврата вход по паролю; данные не теряются благодаря B0.5.3. Продлевать ли срок для мобильного
клиента — открытый вопрос B7.4.

### B4. Попытки офлайн — **O**

  порядку **своим** судьёй, применяет бюджеты шаблона (лишние проверки — не засчитываются, но
  не теряются), пишет события с исходным временем. Ответ — итог для телефона.
- VoxOrd: очередь попыток в `outbox`, отправка при появлении сети, обновление отметок «пройдено».
- Прогресс юнита (learning-service) — та же очередь; проверить идемпотентность записи прогресса.

### B5. Упражнения

Общий шаблон для каждого типа, после B2–B4:
1. **Ключ в пакет** (B3.2): какие поля ключа телефон получает.
2. **Локальный судья**: функция ядра (или ручной порт, если модуля в ядре нет).
3. **Локальное состояние**: бюджет проверок, «показать ответ», второй шанс — хранятся с попыткой в
   `outbox`, переживают убийство приложения.
4. **Проигрыш на сервере**: попытка уходит через B4; итог сервера заменяет локальный.
5. **Проверка на телефоне в авиарежиме**: решить, убить приложение, включить сеть — на сервере та
   же оценка, что показал телефон.

Вместо ручных судей — код движка: `scripts/sync-engine-port.mjs` копирует в `src/enginePort` все

остановки. **Сверка:** 20 цепочек вызовов, записанных на стенде (`scripts/record-stand-scenarios.py`,

**`minimal_pairs` (16.10, вариант A — раздаёт телефон).** Телефон раздаёт сеанс `deal` ядра

ядра и берёт вместо своей (только PRACTICE: иначе 400 `MP_DRAW_NOT_ACCEPTED`; 422
`MP_DRAW_INVALID {fault}`). Повтор того же старта возвращает тот же сеанс; другой открытый сеанс

стартует снова. `weakest` читает `GET /exercises/:id/attempts/probe-history` (скачивается для
таких наборов) плюс свои сеансы, начатые после скачивания истории. Лимит сеансов — только онлайн:
телефон не знает серверный счёт, а отказ при проигрыше терял бы весь сеанс. Сверка: 2 сеанса со
стенда (второй шанс, A/B, отказы, итог) — 22 цепочки. 50/50 нового `multiple_choice` на
телефоне может притушить другой вариант, чем при проигрыше (сид — id попытки); на оценку не влияет.

### B7. Открытые вопросы — решены 16.10

Владелец решил B7.4 сам, остальное отдал на решение с прицелом на точность данных SRS.

1. **Проверки сверх бюджета.** Сервер остаётся судьёй, хранилища «сверх бюджета» нет: бюджеты
   на телефоне считает тот же код движка (`enginePort`), а часы на них не влияют. Единственный
   реальный случай — проигрыш присоединяется к попытке, открытой на вебе раньше, и бюджеты
   складываются. Решение: если открытая на сервере попытка началась **раньше** локального старта,
   журнал её бросает (`DELETE`) и стартует свою, как уже делает `minimal_pairs`. Законченная работа
   с телефона — более полное свидетельство, чем брошенная на вебе. Иначе присоединяется, как сейчас
   (старт дошёл до сервера, ответ потерялся).
2. **Место.** Предела в мегабайтах нет: его заменяет окно «текущий юнит + `offlineUnitsAhead`»,
   пройденное удаляется. Защита: если свободного места меньше 500 МБ, медиа не качаем, и
   настройки говорят почему (`react-native-blob-util` `fs.df()`).
3. **Пробы и GRADED только онлайн**, теперь правилом: локальный старт отказывает при
   `mode: 'GRADED'` или `assignmentId`. Оценённая работа, засчитанная как PRACTICE, исказила бы
   вес свидетельства.
4. **Срок refresh-токена** — вариант B с разными сроками по ролям, см. ssz-platform
   `docs/adr/ADR-012-refresh-token-lifetime-by-role-and-client.md`. Телефон сообщает
   `clientType: "mobile"`; ученику на телефоне 30 дней, учителю 14, владельцу и менеджеру школы
   7, администраторам платформы 12 ч–1 день. При нескольких ролях берётся самый короткий срок.
   Значения меняет `platform_admin` через API (экран на вебе — позже). Предел давности
   времени проигрыша отвязан от токена и поднят до **30 дней** (движок и learning).
5. **Предел очереди** (найдено 16.10). Раньше было 500 записей, лишние самые старые удалялись
   молча. Теперь 2000, а с 80 % заполнения плашка предупреждает. Удалённая запись — потерянное
   свидетельство для SRS.
6. **Веб-копия ядра** синхронизируется на отдельной ветке от `dev` в `ssz-platform-web`, а не
   на ветке PR #65.
